## 1. 應用程式簡介

### 1.1. 用途

`Mountain Hiking App` 是一款專為登山愛好者設計的行動應用程式。其核心用途是提供一個強大且完全離線的 GPX (GPS Exchange Format) 軌跡管理解決方案。使用者可以利用本應用程式進行路線規劃、編輯現有軌跡、合併多段行程、評估路程時間，並在實際登山時記錄自己的軌跡。

### 1.2. 目標使用者

- 喜歡規劃登山行程，需要視覺化編輯 GPX 路線的山友。
- 需要將多個 GPX 檔案（如分段下載的路線）合併成一個完整行程的使用者。
- 希望在山上沒有網路訊號時，仍能可靠地記錄軌跡並對照參考路線的登山者。
- 需要系統化管理個人 GPX 檔案庫的使用者。

### 1.3. MVP 版本核心價值

在當前的 MVP (最小可行性產品) 版本中，我們專注於提供極致的**離線體驗**。所有功能都圍繞著「無網路狀態下的可靠性」進行設計，確保 App 是您在山區最值得信賴的數位夥伴。

## 2. 技術架構

### 2.1. 核心技術棧
- **框架 (Framework)**: Flutter 3.x
- **開發語言 (Language)**: Dart 3.x
- **程式碼規範 (Linter)**: `package:flutter_lints/flutter.yaml`

### 2.2. 專案結構 (Monorepo)
本專案採用 **Monorepo** 架構進行管理，將程式碼模組化以提高複用性與維護性。
```
mountain_suite_monorepo/
│
├── apps/
│   └── mountain_hiking_app/  # 主應用程式，負責 UI 和整合
│
└── packages/
    └── gpx_core/             # 處理 GPX 核心邏輯的本地套件
```
這種結構的好處是，未來若要開發其他相關 App（如網頁版），可以共用 `gpx_core` 的邏輯。

### 2.3. 狀態管理 (BLoC)
- **模式**: BLoC (Business Logic Component)
- **原則**: UI 層透過觸發 **Events** 來通知 BLoC，BLoC 接收 Event 後處理業務邏輯（如呼叫 Repository），並透過 **States** 將結果回傳給 UI。UI 根據不同的 State（如 `Loading`, `Success`, `Failure`）來更新畫面。
- **優點**: 使得業務邏輯與 UI 完全解耦，有利於測試和維護。

### 2.4. 設計原則 (Offline-First)
- **資料儲存**: 使用者產生的所有資料（如軌跡、盤點表）都優先儲存在裝置本機。GPX 檔案的 metadata 透過 `sqflite` 儲存在 SQLite 資料庫中，原始檔案則存放在應用程式的內部檔案系統中。
- **可靠性**: 核心功能（地圖規劃、軌跡記錄等）被設計為完全不依賴網路連線，確保在訊號不佳的山區也能穩定運作。

## 3. 主要依賴套件

以下是從 `pubspec.yaml` 中整理出的關鍵套件及其用途：

| 套件 (Package)              | 用途                                                                 |
| --------------------------- | -------------------------------------------------------------------- |
| `flutter_bloc` / `bloc`     | BLoC 狀態管理的核心框架。                                            |
| `equatable`                 | 輔助 BLoC 進行 State 的比較，避免不必要的畫面重繪。                  |

| `sqflite` / `path_provider` | 用於在裝置本機建立和管理 SQLite 資料庫及檔案路徑。                   |
| `file_picker` / `file_saver`| 提供系統原生的檔案選擇器與存檔功能，用於匯入/匯出 GPX。              |

| `permission_handler`        | 統一處理與請求敏感權限 (如：定位、儲存)，簡化權限管理邏輯。         |
| `intl` / `flutter_localizations` | 處理國際化 (i18n) 與多語言支援。                                   |
| `firebase_core` 等          | (MVP 暫緩) 未來用於串接 Firebase 後端服務 (Auth, Firestore) 的套件。 |

## 4. 程式碼結構 (`lib` 目錄)

### 4.1. 總覽
應用程式的主要邏輯都位於 `lib` 資料夾中。整體遵循 Feature-Driven 的結構，每個主要功能都有其對應的 `screen` 和 `bloc`。

- **`main.dart`**: 應用程式的進入點 (Entry Point)，負責初始化設定、全域 BLoC 提供者 (RepositoryProvider, BlocProvider) 以及路由管理。
- **`lib/src/`**: 核心程式碼目錄。
- **`lib/l10n/`**: 存放多國語系檔案，實現 App 的國際化。

### 4.2. 核心模組說明

| 檔案/模組                               | 對應功能頁面                 | 說明                                                               |
| --------------------------------------- | ---------------------------- | ------------------------------------------------------------------ |
| `home_screen.dart`                      | 第一頁 首頁                  | App 主入口，提供核心功能的快速入口。                               |
| `info_screen.dart`                      | 第二頁 參考資訊              | 提供外部資源連結，如官方網站、登山社群等。                         |
| `gpx_planning_screen.dart`              | 第三頁 GPX 地圖規畫          | 核心功能。在地圖上視覺化編輯 GPX 軌跡、管理航點、AI 路徑規劃。     |
| `gpx_merge_screen.dart`                 | 第四頁 現有 GPX 整併功能     | 將多個 GPX 檔案合併為單一軌跡。                                    |
| `route_evaluation_screen.dart`          | 第五頁 路程評估              | 根據上河地圖時間與使用者體能，評估路程所需時間。                   |
| `equipment_checklist_screen.dart`       | 第六頁 裝備盤點表            | 提供登山裝備清單供用戶盤點、記錄與儲存 (本機)。                    |
| `gpx_library_screen.dart`               | 第七頁 GPX 地圖庫 (本機版)   | **純本機**的 GPX 檔案管理中心，管理儲存在 App 內部空間的軌跡。     |
| `tracking_screen.dart`                  | 第十頁 地圖開啟與軌跡記錄    | 匯入 GPX 參考、透過 GPS 定位、即時記錄軌跡並儲存至本機地圖庫。     |

### 4.3. 本地套件 (`gpx_core`)
位於 `packages/gpx_core`，此套件封裝了所有與 GPX 檔案格式處理相關的底層邏輯，包含：
- **資料模型 (Data Models)**: 定義了如 `Gpx`, `Trk`, `Wpt` 等與 GPX 規格對應的 Dart 物件。
- **解析器 (Parser)**: 負責將 XML 格式的 GPX 字串轉換為 Dart 物件。
- **生成器 (Builder)**: 負責將 Dart 物件轉換回 XML 格式的 GPX 字串。
主應用程式透過依賴此套件來處理 GPX，而非直接操作 XML，實現了邏輯的複用與分離。

## 5. Android 平台配置 (`android` 目錄)

此目錄包含所有 Android 平台的特定設定。

- **`android/app/build.gradle.kts`**:
  - `applicationId`: `com.windsong.mountain_hiking_app`，App 在 Google Play 上的唯一識別碼。
  - `namespace`: `com.windsong.mountain_hiking_app`，定義了 Kotlin/Java 原始碼的命名空間。
  - `signingConfigs`: 設定了發布 (release) 版本所需的數位簽章資訊，用於證明 App 的來源與完整性。

- **`android/app/src/main/AndroidManifest.xml`**:
  - **權限 (Permissions)**: 宣告了 App 運行所需的各項權限，如 `ACCESS_FINE_LOCATION` (精確位置), `ACCESS_BACKGROUND_LOCATION` (背景位置), `FOREGROUND_SERVICE` (前景服務) 和 `WRITE_EXTERNAL_STORAGE` (儲存)。
  - **API Key**: 內嵌了使用 Google Maps Platform 所需的 API 金鑰。

- **`android/app/src/main/kotlin/.../MainActivity.kt`**:
  - Flutter App 在 Android 上的主要活動 (Activity) 進入點，其 package name 已與 `applicationId` 統一，解決了 `ClassNotFoundException` 問題。

## 6. 功能規格 (MVP)

根據 `規格書(mountain_hiking_app)_logoff版.txt`，當前 MVP 版本的功能規格摘要如下：

### 6.1. 首頁 (`home_screen.dart`)
- **目標**: 作為 App 的主入口，提供核心功能的快速導航。
- **移除功能**: 登入/註冊區塊、我的最愛區塊。
- **主要元件**: 一個顯眼的「開始規劃新路線」按鈕（導向第三頁），以及其他核心功能（如 GPX 合併、軌跡記錄）的入口。

### 6.2. GPX 地圖規畫 (`gpx_planning_screen.dart`)
- **目標**: 提供強大的視覺化 GPX 編輯器。
- **資料來源**: 可從「本機地圖庫 (第七頁)」或「裝置的檔案系統」直接上傳 GPX 檔案。
- **核心編輯功能**: 
  - **刪除**: 刪除軌跡點或路段。
  - **新增**: 新增航點 (WPT)。
  - **管理**: 編輯航點資訊、排序。
  - **AI 規劃**: 自動安排航點的最佳順序。
- **輸出**: 可將編輯後的結果匯出成新的 GPX 檔案，或直接儲存/更新至本機地圖庫。

### 6.3. 現有 GPX 整併 (`gpx_merge_screen.dart`)
- **目標**: 將最多 3 個 GPX 檔案合併成一個完整的路線。
- **檔案限制**: 單檔上限 800KB。
- **輸出**: 合併後的 GPX 可直接下載到裝置，或儲存到本機地圖庫。

### 6.4. GPX 地圖庫 (`gpx_library_screen.dart`)
- **目標**: 建立一個**完全離線**的個人 GPX 軌跡管理中心。
- **儲存策略**: 所有 GPX 檔案與其 metadata (名稱、距離、日期等) 皆儲存於 App 的內部儲存空間 (使用 SQLite 和 File System)。
- **核心功能**: 匯入、管理、搜尋、分析、刪除儲存在 App 內的軌跡。
- **風險提示**: 資料無雲端備份。若 App 被解除安裝或資料被清除，所有軌跡將會遺失。

### 6.5. 軌跡記錄 (`tracking_screen.dart`)
- **目標**: 提供即時的 GPS 軌跡記錄功能。
- **核心功能**:
  - **匯入參考**: 可匯入既有 GPX 檔作為路線參考。
  - **記錄**: 獲取使用者當下的 GPS 位置（經緯度、高度、時間），並繪製在地圖上。
  - **控制**: 提供「開始」、「暫停」、「繼續」、「結束」的記錄控制。
  - **儲存**: 記錄結束後，讓使用者命名並將軌跡儲存為新的 GPX 檔案至「本機地圖庫」。
